# Packet 18: runner fixes from the review of part 2 (PR #129)

Read `.handoff/packets/00-architecture.md` (binding). Fix both findings at the root and keep `make verify` green.

1. **Causal failure attribution for parametrized cases** (`src/runner/rescore.rs` around line 271). With a link to `test` and outcomes `test#one` passed, `test#two` failed, the badge is correctly broken, but the failing-test selector excludes both cases, falls back to `test#one`, and history records that the *passing* case failed. Choose the causal failure from `TestEvidence` entries with `admissible == true` and status failed or errored; never fall back to a passing case (if nothing qualifies, record "unknown" and no test id). Regression: `history_names_the_failing_parametrized_case` (it checks the case id and that its diagnostic is in the note).
2. **Workspace package identity in libtest ids** (`src/adapters/mod.rs` around line 199). Turning every `unittests src/lib.rs` target into `lib`, and every `src/main.rs` into `bin`, throws away package identity, so two workspace crates with the same qualified test name collide (duplicate-id error on a valid capture). Keep the stable package/target name from the executable path (`target/debug/deps/<crate>-<hash>`), stripping only the build hash, e.g. `libtest:<crate>:lib:...`. The test index must produce the same id for the same test. Update the dogfood annotations if their ids change (run `make living-spec-refresh`; the auditor must still accept every link), along with any fixtures. Regressions: `workspace_crates_with_same_test_name_get_distinct_ids` and `index_and_adapter_ids_agree` (which must still pass).
