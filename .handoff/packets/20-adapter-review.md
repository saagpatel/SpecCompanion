# Packet 20: adapter fixes from round 2 of the part-2 review (PR #129)

Read `.handoff/packets/00-architecture.md` (binding). Fix all three in `src/adapters/mod.rs` at the root, with the named regressions in `tests/runner.rs` (runner layer: import only core, adapters, runner). Keep `make verify` green.

1. **Libtest display decorations** (around line 113). Libtest prints `test module::case - should panic ... FAILED` (and doc-test mode suffixes such as `- compile fail`, `- should panic`, `(line N)` forms). The adapter keeps the decoration in the id, so a linked `module::case` gets no outcome: the line is unproven/not_executed instead of broken, and the exit code is 0. Strip the recognised libtest display decorations before building the stable id; anything unrecognised after ` - ` stays in the id (conservative). Regressions: `should_panic_failure_breaks_the_linked_line` (the line is broken, the diagnostic attaches, rescore exits 2) and `should_panic_pass_proves_the_linked_line`.
2. **DTD and custom entities in JUnit** (around line 539). The catch-all silently drops quick-xml's DocType and GeneralRef events. So `<!DOCTYPE testsuite [<!ENTITY f "<failure/>">]><testsuite><testcase name="linked">&f;</testcase></testsuite>` parses as passed. Reject any DOCTYPE/DTD and any unresolved or custom entity reference with an input error. Handle the predefined XML entities and character references deliberately. Make the event match exhaustive over the variants that can carry results, so nothing is silently ignored. Regression: `junit_entity_cannot_hide_a_failure` (input error, never a passing outcome).
3. **Timeout notices** (around line 127). `test module::slow has been running for over 60 seconds` is a normal notification line, and right now it makes a valid run be rejected. Recognise it separately. Regression: `libtest_timeout_notice_is_accepted` (the notice, then the completed testcase, then the matching summary, which parses fine).
