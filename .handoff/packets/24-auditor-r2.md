# Packet 24: three false-green fixes from round 2 of the part-3 review (PR #131), plus the auditor's stated scope

Read `.handoff/packets/00-architecture.md` (binding). Fix each finding at the root with a named regression. Keep `make verify` green, keep the dogfood at 33 accepted links (`living-spec audit living-spec --tests .` exits 0), and keep every earlier cheating regression challenged.

1. **JavaScript block comments are not nested** (`src/agents/syntax.rs` around line 47). The lexer treats them as nested, so in `/* /* */ return; // */\nexpect(export_timestamp(30)).toBe(30);` it swallows the `return` up to the later `*/`, while JavaScript actually executes the return and never reaches the assertion. JS/TS block comments end at the first `*/`; only Rust nests. More generally, any statement that can end the test early (`return`, `throw`, `process.exit`, early `return` in Python, `std::process::exit`, `panic!` outside a supported should_panic shape) is an unsupported shape, so the link is challenged. Regressions: `js_block_comment_is_not_nested`, `early_return_before_assertion_is_challenged` (JS, Python, Rust).
2. **`audit --write` and `link --write` carry overrides forward** (`src/cli/audit.rs` around line 88, plus `link --write` through `audit.extra`). A human override must apply only to the exact binding it was given for. Record the binding inside the override (`test_id`, `fingerprint`, requirement `revision`). Treat an override as inactive whenever any of the three differs; keep it as inactive history (e.g. `override_history`), never as live acceptance. Regressions: `override_invalidated_when_test_changes`, `override_invalidated_on_rename`, `override_invalidated_when_requirement_changes`, each through both write commands.
3. **Numeric coverage pooled across unrelated assertions** (`src/agents/auditor.rs` around line 39). For `Export timestamps at 30 and 90.`, `assert export_timestamp(30) == 30` plus `assert unrelated(90) == 90` is accepted. Count a requirement number as covered only when it appears in an assertion (or its supported `let` provenance) that is itself requirement-relevant. Regression: `unrelated_assertion_cannot_supply_required_number`.
4. **State the auditor's scope** in `README.md` (Living Spec section) and in `.handoff/packets/00-architecture.md`. The auditor is a deterministic, best-effort static check aimed at lazy or accidental non-tests: placeholders, irrelevant or tautological assertions, unexecuted or unsupported shapes. It is not a sandbox and not a proof that a test is adversarially sound. A deliberately obfuscated test can still mislead it. Unsupported shapes are always challenged. A green badge means "a passing test the auditor could relate to this line", never "proven correct".
