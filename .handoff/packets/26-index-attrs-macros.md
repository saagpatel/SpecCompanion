# Packet 26: two test-index fixes from round 3 of the part-3 review (PR #131)

Read `.handoff/packets/00-architecture.md` (binding). Fix both in `src/agents/test_index.rs`, each with a named regression in `tests/agents_review.rs` (agents layer: import only core, adapters, agents). Keep `make verify` green and the dogfood at 33 accepted links.

1. **Conditional or unsupported attributes** (around line 638). `#[test] #[cfg_attr(test, should_panic)] fn check_timestamp() { assert_eq!(export_timestamp(30), 30); }` passes under Cargo because the failing assertion panics, but the index records `should_panic = false` and the auditor accepts it. Record every attribute on a test. Any attribute other than plain `#[test]`, `#[ignore]` (the test is not executed, so the link is unproven) and plain `#[should_panic]` / `#[should_panic(expected = "...")]` (including `cfg_attr`, `cfg`, unknown attributes, and any attribute from a macro crate) makes the test an unsupported shape, so the link is challenged. Regression: `cfg_attr_should_panic_is_challenged`.
2. **Macro token trees** (around line 649). `stringify!(#[test] fn smoke() {})` creates a fabricated test entry, and if a real `smoke` exists in that scope, duplicate detection rejects the whole index. Skip complete macro invocations with every delimiter (`()`, `[]`, `{}`) before discovering declarations; for macro_rules definitions, skip the whole body. Regressions: `stringified_test_is_not_indexed` and `stringified_test_does_not_collide_with_real_test`.
