# Packet 32d: make the subject resolver handle real crate layouts, fail closed

Read `.handoff/packets/30-mutation-architecture.md` and `32b-mutation-subject.md`. The 32b result is on your base but the resolver is too conservative and has soft spots. Your target crate is `living-spec/` itself (dogfood): `src/` has many `mod x;` file modules, `mod.rs` directories and `pub use` re-exports. A resolver that rejects external modules makes every dogfood link `unsupported`, which defeats the tier.

## Scope (`living-spec/src/mutation/subject.rs`, `generate.rs` only if needed; no runner work)
1. **External modules:** resolve free `fn` definitions across all `src/**/*.rs` of the package (the files reachable by `mod` declarations; treat any `.rs` file under `src/` as candidate and verify reachability by following `mod x;` to `x.rs` / `x/mod.rs`, `#[path]` attributes make the package unsupported). A `#[cfg(test)] mod x;` (or `#[cfg(test)]` on any enclosing module) excludes that file's contents. Any other `cfg`/`cfg_attr` on an item or module => skip that item (fail closed); if skipping removes the only candidate, `unsupported`.
2. **Function extents:** compute the item extent robustly: find the fn name, then the signature end as the first `{` or `;` at paren/bracket/angle depth 0 outside strings/comments; if the signature contains a `where` clause with `{` or `const` generics braces, mark the function uncertain and skip it. Body = matching braces using the lexer's token stream (strings, chars, raw strings, lifetimes, comments handled). Add regressions for where-clauses with braces, nested closures, raw strings containing braces, and lifetimes like `'a`.
3. **Ambiguity:** a name is a subject only if exactly one non-test free `fn` with that name exists in the package, counting definitions inside `macro_rules!` bodies and any macro invocation that could generate fns as potential competing definitions (if the package defines or invokes macros that expand to `fn $name`, treat all names as ambiguous only when the macro body contains `fn`). Methods in `impl` blocks do not collide with free functions but `.name()` calls never count as calls to free `name`.
4. **Cargo manifest:** parse with a real, small TOML-subset approach that fails closed: tables and inline tables including multi-line values; any dependency (in `[dependencies]`, `[dev-dependencies]`, `[build-dependencies]`, target tables) with `path` must resolve inside the crate dir; `workspace = true` / `[workspace]` membership => `unsupported: dependencies outside crate`; anything unparseable => unsupported. Do not add a TOML dependency; if a tiny parser is infeasible, use a conservative check that rejects whenever the strings `path`, `workspace`, or `git` appear in dependency tables, and document it.
5. Update the sample crate with an external-module layout (`mod a;` file and a `b/mod.rs`) and a `#[cfg(test)] mod`. Tests: `external_module_function_resolves`, `cfg_test_module_file_excluded`, `path_attribute_module_unsupported`, `where_clause_brace_function_skipped`, `raw_string_braces_do_not_end_function`, `macro_generated_fn_makes_name_ambiguous`, `workspace_inherit_unsupported`, `multi_line_inline_dependency_table_parsed`, `dogfood_crate_functions_resolve` (run the resolver on `living-spec/` itself for a known test and assert at least one subject resolves).
