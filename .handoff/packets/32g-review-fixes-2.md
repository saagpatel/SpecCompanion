# Packet 32g: two remaining review findings on the mutation engine (PR 142)

Read `.handoff/packets/30-mutation-architecture.md`. Base = the PR 142 branch. Fail closed, one named regression per finding. Files: `living-spec/src/mutation/subject.rs` and tests.

1. **Manifest scanner misses commented headers.** `[dependencies] # comment` leaves the dependency-table state false, so a following `external = { "path" = "/outside" }` bypasses both guards. Replace the stateful scan with a conservative rule: strip `#` comments (outside quoted strings) from every line first, then if the manifest has **any** quoted key (a `"..."` or `'...'` token directly followed by optional spaces and `=`) outside the `[package]` table, or any `path`/`git`/`workspace` key in any table other than `[package]`/`[lib]`/`[[test]]`/`[[bin]]` that is not provably inside the crate (relative path without `..` and not absolute), return `unsupported: dependencies outside crate`. If a header line cannot be parsed (anything after `]` besides whitespace or a comment), also unsupported. Regression `commented_header_with_outside_quoted_path_unsupported`, plus `comment_after_header_still_parsed` for a harmless manifest.
2. **Shadowing misses `let mut` and destructuring.** `let (value, _) = (|| 1, ()); assert_eq!(value(), 1);` wrongly resolves a free `value`. Fail-closed rule: a called name is a subject only if, within the test body, every occurrence of that identifier token is directly followed by `(` (a call) and none is preceded by `let`, `mut`, `ref`, `|`, `,` inside a pattern, or appears in a closure parameter list, `fn` parameter list, `for` pattern, `if let`/`while let`/`match` arm pattern. Simplest implementation: if the identifier appears anywhere in the test body in a non-call position, or appears anywhere in a pattern position, it is shadowed and not a subject. Regressions `destructured_closure_does_not_select_free_fn`, `let_mut_closure_shadows_free_fn`, `closure_param_named_like_free_fn_shadows`, and a positive `plain_call_still_resolves`.
