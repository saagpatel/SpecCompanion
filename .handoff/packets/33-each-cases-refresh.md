# Packet 33: two fixes from round 2 of the part-8 review (PR #137)

Read `.handoff/packets/00-architecture.md` (binding). Fix both with named regressions; keep `make verify` green and the dogfood at 33/33.

1. **`.each` case inventory** (`src/agents/test_index.rs` around line 960). For `test.each([[1], [2]])('export %i', ...)`, the index records only the base declaration, so a filtered JUnit report containing only the passing `export 1` case can score the line proven, because nothing says `#2` is missing. Fix: when the `.each` (and pytest `parametrize`) table is a literal list the index can enumerate, record every case id (`#1`, `#2`, …, formatted the way the adapter maps titles) in the identity inventory, so a missing case is `not_executed`. When the table can't be enumerated statically (a variable, a function call, a spread, a template table), the test's case set is unknown, so challenge it as an unsupported shape. Regressions: `filtered_each_report_missing_case_is_not_proven`, `non_literal_each_table_is_challenged`, `pytest_parametrize_literal_cases_are_inventoried`.
2. **`scripts/refresh-dogfood.sh` drops failure results** (around line 26). With `set -e`, a valid score that has broken lines (exit 2) aborts before the refreshed artifacts are copied back, and the EXIT trap deletes the staged status/history/HTML. Fix: publish the staged artifacts when the score exits 0 **or 2** (a broken status is honest evidence and must be recorded), still exit with the score's code, and preserve the previous artifacts only on exit 1 (input error). Update the Ruby regression in `scripts/test-ci.rb` (it lives in the dogfood-ci layer) and add `refresh_records_broken_status` there or as a shell test.
