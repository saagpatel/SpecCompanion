# Packet 34: libtest output with ANSI colour codes must parse

Root cause of the CI-only failure of `score_detects_a_real_failure_in_a_temporary_crate_copy`, reproduced locally with `CARGO_TERM_COLOR=always cargo test --offline --test pipeline score_detects`: the `dtolnay/rust-toolchain` action sets `CARGO_TERM_COLOR=always`, so the inner `cargo test` prints coloured result lines (`test x ... \x1b[32mok\x1b[0m`). The libtest adapter (`src/adapters/`) doesn't recognise them, the outcome is missing, and the line scores `unproven not_executed` (reasons `[NotExecuted]`, no tests). This is a product bug too: a user with colour forced on gets failing tests reported as "not executed", and `score` exits 0 instead of 2.

Fix: strip ANSI escape sequences (CSI `ESC [ … final-byte`, plus OSC hyperlink sequences `ESC ] … ESC \` or BEL) from each line before any libtest parsing (result lines, `Running` headers, `failures:` sections, summaries). JUnit is unaffected. Regressions in `tests/runner.rs`: `coloured_libtest_output_parses_like_plain` (the same capture with and without colour gives identical outcomes) and `coloured_failure_breaks_the_line` (exit 2 through rescore). Keep `make verify` green, and confirm that `CARGO_TERM_COLOR=always make verify` also passes.
